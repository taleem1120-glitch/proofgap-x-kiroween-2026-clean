# ProofGap X adversarial benchmark protocol

Status: design specification; not execution evidence.

## Purpose
Evaluate whether ProofGap X distinguishes independent evidence from derivative repetition, abstains when independence is unresolved, and remains deterministic and resource-bounded.

## Corpus construction
Use generated, labeled cases only. Each case records:
- scenario ID and generator seed;
- ground-truth origin graph;
- claim-support labels;
- expected decision band (corroborated / single-origin / unresolved / unsupported);
- adversarial transformation applied.

Never use benchmark labels as evidence of real-world accuracy. Keep the generator and expected labels versioned.

## Required challenge families
1. Origin inflation: one root copied into many outlets, aggregators, summaries, and social posts.
2. Shared-root masking: apparently distinct primary references with common URL, identifier, saved-file identity, or declared lineage cues.
3. Citation laundering: secondaries cite one another, circular chains, and chains with no resolvable primary.
4. Content reuse: exact, partial, reordered, paraphrased, and multilingual shared passages. Text similarity is a cue, not proof of origin.
5. Leave-one-origin-out: remove each support root in turn and measure whether the claim's support threshold survives.
6. Source-order invariance: permute references, evidence order, and input order; canonical outputs should remain stable where semantics are unchanged.
7. Missing/unsafe evidence: absent files, malformed text, unsupported formats, symlinks, traversal, and invalid encodings.
8. Resource exhaustion: repetitive inputs, large files, high citation-pair counts, and budget exhaustion. Exhaustion must be surfaced as incomplete/manual review, not as a clean negative.

## Metrics
Report counts and rates, with denominators and scenario breakdowns:
- false corroboration rate: unsupported or single-origin cases incorrectly labeled independently corroborated;
- false abstention rate: truly independent labeled cases incorrectly withheld;
- detection coverage: fraction of challenge cases receiving the intended signal;
- order-invariance rate: fraction of permutations preserving expected semantic result;
- incomplete-scan disclosure rate: resource-limited cases explicitly marked incomplete;
- determinism: repeated serialized output hashes for identical inputs;
- resource envelope: observed time and memory by size bucket.

## Execution requirements
- Run the same corpus on supported Node versions and record exact commit SHA, runtime versions, command, seed, and output hashes.
- Separate unit, adversarial, integration, browser, and performance results.
- Do not publish superiority or real-world accuracy claims from synthetic cases.
- Keep failed cases and raw results; do not silently tune labels or remove difficult cases after seeing results.

## Release gate
A release candidate is not ready until all required test suites pass, incomplete scans fail closed, the Showcase is regenerated by the committed build command and matches byte-for-byte, and benchmark results are reproducible from a documented command.
