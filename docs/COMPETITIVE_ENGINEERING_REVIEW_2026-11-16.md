# ProofGap X — Competitive engineering review, 16 November 2026

**Classification:** engineering appraisal, not an independent certification or prediction of a win. All evidence refers to PR #6 unless explicitly described otherwise.

## Real strengths supported by code
- The central innovation is **declared source independence**, not counting documents as corroboration by quantity alone.
- A common deterministic evidence-core powers both a case-investigation app and a separate research-citation app.
- Reports expose assumptions, graph relationships, disagreements and abstention instead of hiding unknown lineage.
- Local integrity hashing checks byte identity; neither hashes nor declared metadata prove original authorship or truth.
- Offline self-contained viewer, CSP, text-only insertion, bounded JSON input, preserved JSON export and ten UI languages.
- Playwright-based Chromium cases run two apps at 360px, 411px and 1280px with ten language changes; a real overflow defect was found and repaired. This does not establish human-reviewed linguistic accuracy.
- A bilingual Arabic/English **case authoring and local analysis assistant** now prepares valid case JSON, runs the ORIGINAL shared analysis engine on the phone, and downloads its deterministic report. The generated browser engine bundle is tested for byte-identical output against Node.js and its build is checked for reproducibility. This is browser-side analysis of **declared source relationships**, not native forensic acquisition, authentication or real-world source verification.

## Performance proof, not a guaranteed SLA
An author-generated scaling workload in `bench/engine-scaling-check.js` checks 12, 36, 72, 144, and 288 independent source/evidence pairs, plus reproducible policy output, under Node 20/22 CI. On one GitHub Node 22 runner on 2026-11-16: approx. 6.67, 3.59, 8.09, 17.81, and 60.32 ms respectively. Measurement is machine-sensitive (warmup, GC and runner load are uncontrolled); measured RSS at end of the synthetic process is not a peak memory profile. **Do not** advertise any of these as a real-world latency promise, throughput percentile, or vendor benchmark.

## Impact gaps that matter more than extra cosmetic features
1. **Mobile analysis now works for structured cases**; remaining usability gaps are direct PDF/Word ingestion, multi-link editing, comprehensive on-screen findings, complete locale support for the case builder, and verified real-device UX. Do not confuse its on-phone workflow with verified evidence acquisition.
2. **Source verification**: users declare original/copy relations. Lexical cues for hidden dependence are advisory, cannot prove lineage, and translation/paraphrase remains weakly supported.
3. **Independent verification**: no blind third-party labeled source families, no measured real-world precision/recall/FPR, no fair matched competitor comparison, and no external pentest.
4. **Ten languages are UI-locales, not complete multilingual analysis**: source quotations and rule-generated narrative explanations remain original-language. Expert translation review remains incomplete.
5. **Kiro competition narrative**: the factual log records Kiro Web Vibe, Playwright Power and specs as files, but does not evidence Kiro Hooks, Crew, spec execution UI or other unperformed features. Honesty helps technical credibility.
6. **Operational integration**: no native PDF/Word/phone-acquisition ingestion or automatic provenance attestation. Never present it as a comprehensive DFIR acquisition suite.

## Release decisions
**Can confidently show judges**: two functional offline applications, synthetic proof-echo scenario, declared source-lineage diagram, report export, honest limitations and browser/CI evidence.

**Do not claim**: 100% accuracy, regulatory certification, verified source-authenticity, leading commercial product, superiority to forensic suites, or public deployment of draft-only features.

**Next highest ROI after the new end-to-end browser workflow**: richer safe evidence linking and review of graph provenance, independent hidden-dependence evaluations on externally adjudicated datasets, and higher-coverage multilingual explanation review. Never promise PDF/phone extraction until implemented and tested.

**Competition gate**: finish screenshots and a final mobile UX check, review PR, deploy, smoke-test deployed public links, record an English sub-3-minute YouTube demo with actual functionality and Kiro evidence, then complete Devpost. A full external commercial audit is a separate quality milestone, not an assumed contest prerequisite.
